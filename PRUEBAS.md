# Pruebas manuales — Tienda GM

Casos de prueba ejecutados manualmente contra la API (`http://localhost/tienda-gm-api`, XAMPP local) y la base de datos `tienda_gm`. Los casos backend (P01–P10) se ejecutaron con `curl` + verificación directa en MySQL el 2026-09-09, usando cuentas de prueba desechables (creadas y eliminadas al finalizar cada caso, sin dejar datos residuales). El caso P05 (PDF) es client-side puro y se verificó por revisión de código, no por ejecución en navegador — ver nota al pie.

| ID | Módulo | Caso de prueba | Pasos | Resultado esperado | Resultado obtenido | Estado |
|----|--------|-----------------|-------|---------------------|---------------------|--------|
| P01 | Autenticación (admin) | Login con credenciales incorrectas | `POST /auth/login` con correo inexistente y contraseña inválida | 401 y mensaje "Correo o contraseña incorrectos.", sin token emitido | 401, `{"mensaje":"Correo o contraseña incorrectos."}` | ✅ Pasa |
| P02 | Autenticación (cliente) | Login con credenciales incorrectas | `POST /clientes/login` con correo inexistente y contraseña inválida | 401, mismo mensaje genérico (no revela si el correo existe) | 401, `{"mensaje":"Correo o contraseña incorrectos."}` | ✅ Pasa |
| P03 | Ventas | Registrar venta de un producto con talla → descuenta stock de esa talla específica | Cliente autenticado hace `POST /ventas` con `id_talla` de un producto con variantes, `cantidad:1`. Venta #53 registrada, total $92.00 | ✅ Pasa |

Se compara `producto_tallas.stock_actual` y `productos.stock_actual` antes/después | Ambos contadores de stock suben en la cantidad comprada, dentro de una transacción atómica | Talla 35 del producto #12: `producto_tallas` 2 → 7, `productos` 9 → 14 (compra #21, +5 unidades) | ✅ Pasa |
| P05 | Ventas (cliente) | Generación de factura PDF | Tras registrar un pedido desde la tienda, `descargarFacturaActual()` / `verFacturaHistorial()` invoca `generarFacturaPDF()` (jsPDF + jspdf-autotable) con los datos de la venta | Se genera un PDF con encabezado de marca, datos del cliente, tabla de productos y totales | Verificado por revisión de código (`ventas.page.ts` / `tienda.page.ts`): la función arma correctamente el documento (encabezado, tabla `autoTable`, totales) y compila sin errores. **No se verificó visualmente en navegador** — recomendado antes de cerrar el proyecto | ⚠️ Verificado por código, pendiente de confirmación visual |

| P07 | Ventas (envío) | Confirmación de recepción del cliente | Admin cambia `estado_envio` a `despachado` (`PUT /ventas/{id}/estado-envio`); luego el cliente dueño del pedido llama `PUT /ventas/{id}/confirmar-recepcion` | `confirmado_cliente` pasa a 1 y se notifica al admin | `estado_envio='despachado'`, `confirmado_cliente=1` tras la llamada del cliente | ✅ Pasa |
| P08 | Configuración | Activar/desactivar IVA | Admin hace `PUT /configuracion` alternando `iva_activo` entre `'0'` y `'1'`; se relee con `GET /configuracion` | El valor persiste y se refleja inmediatamente en las lecturas siguientes | `0 → 0` (sin cambio real) → `1` → confirmado en `GET`. Se restauró a `0` (valor original del proyecto) al finalizar | ✅ Pasa |
| P09 | Favoritos | Agregar y quitar un producto de favoritos | Cliente autenticado hace `POST /favoritos` dos veces seguidas sobre el mismo producto (toggle) | Primera llamada lo agrega (`favorito:true`), segunda lo quita (`favorito:false`); `GET /favoritos/cliente/{id}/ids` refleja el estado en cada paso | Agregar → `{"favorito":true}`, ids `[12]`. Intenta de nuevo en unos minutos."}` en el 6.º intento (verificado en sesión de seguridad previa) | ✅ Pasa |

## Notas

- Todas las pruebas contra la API se hicieron con cuentas y datos **desechables**, eliminados inmediatamente después de cada caso (usuarios `test_qa*@tiendagm.com`, cliente `cliente_qa3@test.com`, venta #53, compra #21). No quedan residuos en la base de datos de producción local.
- P05 es la única prueba **no** ejecutada de punta a punta (requiere un navegador real para confirmar visualmente el PDF descargado). Antes de dar el proyecto por cerrado, se recomienda: iniciar sesión como cliente, completar un pedido y confirmar que el botón "Descargar factura PDF" produce un archivo legible con los datos correctos.
- Los entornos usados: Apache + MySQL de XAMPP corriendo en local, base de datos `tienda_gm`.
